# Samsara Safety Alerts for Telegram

An aiogram v3 bot that monitors one or two Samsara organizations. A bot administrator selects the Samsara organization and trucks for each Telegram group. The bot sends alerts for `Braking` safety events on selected trucks, including the truck, driver, location, date and time, and available camera video.

## Setup

1. Install Python 3.10 or later.
2. Install FFmpeg and add `ffmpeg.exe` to `PATH`. The bot uses it to prepare silent MP4 videos for Telegram.
3. Create a virtual environment and install dependencies:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

4. Copy `.env.example` to `.env` and set:
   - `API_KEY` — API token for the first Samsara organization.
   - `API_KEY2` — optional API token for a second organization.
   - `TELEGRAM_BOT_TOKEN` — token from BotFather.
   - `BOT_ADMIN_IDS` — one or more primary administrator Telegram IDs, separated by commas. Run `/myid` after starting the bot to find your ID, then add it here and restart the bot.
5. Add the bot to each Telegram group. A bot administrator runs `/setup` in the group, selects a Samsara organization, and selects the trucks for that group. Repeat `/setup` to add trucks from another API. Truck assignments are stored separately for each group.

## Samsara API permissions

Safety events require `Read Safety Events & Scores`. For video, the bot first looks for an uploaded high-resolution Road camera clip near the event time through `GET /cameras/media`; if needed, it requests an HD clip through Media Retrieval. This requires `Read Media Retrieval` and `Write Media Retrieval`. If HD media is unavailable, the bot tries a short low-resolution clip. Availability depends on camera support and the organization's monthly quota.

`/trucks` and the video telematics overlay require `Read Vehicle Statistics` under Vehicles. Driver names and assignments use `Read Drivers` and `Read Assignments` under Drivers and Assignments. Enable these permissions on each API token separately. If driver profiles or historical stats are unavailable, the bot still sends the event using the data that is available.

All event, history, and video timestamps use New York time (`America/New_York`), including daylight-saving changes. `EVENT_TIMEZONE` remains in `.env` for compatibility; the bot always uses New York time.

## Behavior

- Samsara polling runs every 30 seconds (`POLL_INTERVAL_SECONDS`).
- On the first run, the bot checks the previous 10 minutes (`INITIAL_LOOKBACK_MINUTES`).
- SQLite database `samsara_bot.sqlite3` stores polling checkpoints and sent-event IDs to prevent duplicates after a restart.
- Automatic alerts and `/history` preserve the source resolution up to 1920×1080, remove audio, and add available driver, truck, location, and speed details. Historical speed samples are rendered as a graph. Videos are compressed only as much as needed to fit Telegram's 49,000,000-byte upload limit and are sent as silent MP4 videos.
- The driver name, speed badge, and graph are generated by the bot from Safety Events and Vehicle Stats. This is a custom overlay, not a Samsara Dashboard export or Authenticity Report. The source video remains silent.
- If the source clip cannot be processed, the bot requests a 12-second HD clip, then tries low-resolution clips of 12, 8, and 5 seconds. If no video can be retrieved or sent, the bot reports that video is unavailable; it does not send a link.
- `/trucks` and `/locations` show selected trucks and their latest GPS locations.
- `/history` shows harsh-braking events for a selected truck from the last 6 days (`HISTORY_LOOKBACK_DAYS`), in pages of 10. When `VIDEO_TELEMATICS_OVERLAY` is enabled, the bot adds the driver, truck, location, speed, and speed graph to the video. Graph availability depends on Samsara Vehicle Stats. If video is unavailable, the bot sends the event details with a video-unavailable notice.
- `BOT_ADMIN_IDS` defines primary administrators. Administrators can grant or revoke access with `/add_admin Telegram_ID` and `/remove_admin Telegram_ID`; `/admins` lists administrators. A primary administrator configured in `.env` cannot be removed with the command.
- Only bot administrators can run `/setup`. Events are delivered to groups where the truck is selected. The same organization and truck can be assigned to multiple groups.

## Telegram Mini App (admin and driver PTI)

The English admin Mini App includes Trucks, PTI, Alerts, and Reports. Trucks can be filtered by company; selecting a truck shows its Telegram notification groups, assigned Telegram driver account, and recent harsh-braking events. The PTI tab lets admins configure the schedule and review each driver's latest photo submission. Alerts searches braking events by New York date range and truck. Driver accounts receive a separate Today, My PTI, and Activity interface with private PTI history.

Set `WEBAPP_URL` in `.env` to the public HTTPS address that serves this app, and set `WEBAPP_HOST`/`WEBAPP_PORT` for the local aiohttp listener (defaults: `127.0.0.1:8080`). Telegram Mini Apps require HTTPS; expose the local listener through your HTTPS reverse proxy or tunnel. Start the bot, open its private chat as a bot administrator, and run `/app`. In a truck's detail view, an admin can link one Telegram user ID to the truck; the driver obtains that ID with `/myid`, starts the bot in a private chat, and opens the same app with `/app`. The API verifies Telegram `initData`; admin-only endpoints remain restricted to bot administrators while drivers can access only their own assigned PTI account.

Admins set the PTI interval (1–168 hours) in the PTI tab. The driver app shows the next due time and allows submission of six required photos: front, rear, driver side, passenger side, cabin, and dashboard/odometer. A driver can start a recurring inspection four hours before its due time (for a 24-hour schedule, after 20 hours); the first inspection and a returned inspection can be submitted immediately. If a driver has not submitted by six hours after the deadline (30 hours on a 24-hour schedule), the bot sends one automatic reminder for that PTI cycle. Admins can also send a direct reminder at any time. Admins may return the latest PTI with a required reason; the driver receives a private Telegram notice, and a new inspection is immediately required. Photos are captured through the live camera using `getUserMedia`; the app has no gallery upload control. Drivers can review, retake, or delete each capture before submitting. PTI submissions and private photo files are stored in SQLite metadata and the local `pti_uploads/` directory; keep that directory with the database in backups and protect it as confidential fleet data. The WebApp must be served over HTTPS and the driver must grant camera permission.
